# تحویل نهایی برای GitHub — ۱ اکتبر ۲۰۲۶

اصلاحات ظاهری تحویل قبلی در ZIP جدید مالک موجود بودند. سورس صفحه‌ها، CSS، JavaScript، داده‌های پترن و فوتر تأییدشده حفظ شده‌اند. ریپوی آنلاین هنوز commit قدیمی `a4a0446b3e5bd0cba3e49c1a5edbc720dee24bf1` بود؛ Push قبلی با fetch first رد شده بود.

## اصلاحات انتشار

- `build/public-assets.js` دارایی‌های `assets` و `fonts` ریشه را با `public` ادغام می‌کند. فایل‌های `public` اولویت دارند. ورودی‌ها جابه‌جا یا حذف نمی‌شوند و خروجی موقت `.cache` در git ثبت نمی‌شود.
- `build:pages` و `preview:pages` از base برابر `/marpich-sanat/` استفاده می‌کنند. build عادی برای بک‌اند یا ریشه دامنه همچنان base برابر `/` دارد.
- URLهای تصاویر، دانلودها و گزینه‌های fallback که هنگام build فایلشان موجود نیست نیز prefix درست Pages می‌گیرند.
- workflow روی main، نصب وابستگی‌ها، بررسی ساختار، build مخصوص Pages و انتشار dist را اجرا می‌کند.
- `check:assets` هر دو محل دارایی‌ها را بررسی می‌کند؛ نیازی به انتقال اجباری تصاویر قدیمی Clone نیست.
- ZIP شامل تاریخچه git، node_modules، dist، cache یا آرشیوهای پروژه نیست. ۹ فونت اصلی Peyda و دو SVG فرایند همکاری در آن هستند. تصاویر سنگین طبق درخواست مالک در ZIP نیستند.

## بررسی فعلی

- `npm run check`، build عادی و build مخصوص Pages موفق شدند.
- ۱۲ صفحه در ۱۱ عرض از ۳۲۰ تا ۲۵۶۰px بررسی شدند: ۱۳۲ حالت؛ بیرون‌زدگی افقی بدنه، متن و بریدگی متن در اسکن دیده نشد. پیمایش مجاز داخل جدول‌ها مستثناست. عنوان‌های فشرده چهار مرحله همکاری و فلش‌های تزئینی از شمارش متن توضیحی جدا هستند.
- منوی فعال آبی در هر ۱۲ صفحه، CTA در هفت عرض، SVG همکاری، مشتریان بدون کنترل یا scrollbar، underline فقط روی label و چهار دکمه بارگذاری بررسی شدند.
- متن‌های توضیحی در سه عرض کوچک جاستیفای، با خط آخر راست‌چین و اندازه حداقل ۱۴px هستند.
- موج و نور هر ۴۶ لایه پترن در موبایل و دسکتاپ حرکت کردند. هندسه مشترک هدر و قاب تیره درباره‌ما، تماس و مقالات، ساعت مشترک انیمیشن و reduced-motion بررسی شدند.
- هر ۹ وزن Peyda در مرورگر بارگذاری شدند؛ درخواست‌های فونت در مسیر Pages پاسخ ۲۰۰ گرفتند.
- SVG اصلی عکس درباره‌ما از همان ریپو با ابعاد ۱۳۱۱×۶۲۸ برای بررسی استفاده شد. در شش اندازه نسبت اصلی و contain حفظ شد و تمام عکس در نمای اول قرار داشت. این تصویر سنگین صرفاً در بررسی استفاده شد و داخل ZIP تکرار نشده است.
- نسبت و ارتفاع عکس خانه با fixture کنترل‌شده بررسی شد؛ عکس سنگین PNG خانه در ورودی مالک نبود. صحت بصری عکس خانه با assets اصلی محلی باید در Preview بررسی شود.
- URLهای عمومی ۱۲ HTML و همه CSSها، شامل fallbackهای تصویر، base درست دارند.
- ادغام root/public، اولویت public، کپی فونت، پاک‌سازی cache قدیمی و حفظ فایل‌های اصلی در fixture مستقل بررسی شد.

گزارش خام: `responsive-github-pages.json`، `interactions-github-pages.json` و `github-delivery-check.json`.

## پیش از Push

راهنمای مرورگری `GITHUB-UPLOAD.html` در همین پوشه و راهنمای متنی `../GITHUB-UPLOAD.md` را بخوانید. ۱۵ مسیر مرجع در ZIP مالک و ریپوی قدیمی پیدا نشدند؛ فهرست در `github-assets-missing.json` است. آن‌ها ممکن است در assets محلی مالک باشند. پس از ادغام فایل‌ها، `npm run check:assets` را اجرا کنید. build موفق وجود همه تصاویر را تضمین نمی‌کند.

این تحویل شامل اتصال جدید Backend یا CMS نیست؛ وضعیت قابلیت‌ها و لینک‌های placeholder در README و سند بک‌اند باقی است.
